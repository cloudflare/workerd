Look up autogate: $ARGUMENTS

All autogates are defined as `V(KEY)` entries in the `WORKERD_AUTOGATES(V)` macro in
`src/workerd/util/autogate.h`. The `AutogateKey` enum, the config string, and the
iteration list (`getAutogateKeys()`) are all generated from that single macro, so they
cannot get out of sync. The config string is derived automatically from the enum name:
`SCREAMING_SNAKE_CASE` becomes kebab-case (lowercase, `_` becomes `-`), prefixed with
`workerd-autogate-`. For example, `AutogateKey::MY_NEW_FEATURE` becomes
`workerd-autogate-my-new-feature`.

**If no argument is provided (empty or blank), list all autogates:**

1. Read the `WORKERD_AUTOGATES(V)` macro in `src/workerd/util/autogate.h`.
2. For each `V(KEY)` entry, read the adjacent `/* ... */` comment for a description.
3. Derive the config string from the key as described above.
4. Output a summary table:

   | Autogate    | Config string                | Description                    |
   | ----------- | ---------------------------- | ------------------------------ |
   | `ENUM_NAME` | `workerd-autogate-enum-name` | Brief description from comment |

   Include the total count of active autogates.

**If an argument is provided, look up that specific autogate:**

1. **Find the macro entry.** Search the `WORKERD_AUTOGATES` macro in
   `src/workerd/util/autogate.h`. The argument may be the enum name (e.g.,
   `SOME_FEATURE`), the kebab-case string, or a partial match. Match
   case-insensitively, treating `-` and `_` as equivalent.

2. **Find usage sites.** Search for where the autogate is checked:

   ```
   rg -n 'AutogateKey::<NAME>' src/
   ```

   The check API is `util::Autogate::isEnabled(AutogateKey::<NAME>)`.

3. **Find tests.** Search for both the enum name and the kebab-case string in test
   files:

   ```
   rg -n '<NAME>|<kebab-name>' src/ -g '*.wd-test' -g '*-test.js' -g '*-test.ts' -g '*-test.c++'
   ```

   Test hooks to look for:
   - The `@all-autogates` test variant (generated by default for every test target).
   - `Autogate::initAutogateForTest({AutogateKey::<NAME>})` in C++ tests.
   - The `autogates` config option in `.wd-test` files, which takes the full prefixed
     string, e.g. `autogates = ["workerd-autogate-<kebab-name>"]`.

4. **Output:**
   - **Enum**: `AutogateKey::<NAME>` (file:line of the macro entry)
   - **Config string**: `workerd-autogate-<kebab-name>` (derived from the enum name;
     not stored anywhere in the source)
   - **Usage sites**: file:line list of where the autogate is checked
   - **Tests**: file:line list of tests that reference this autogate
   - **Notes**: Autogates are temporary and should be removed once the change is fully
     rolled out — see the removal instructions in the `autogate.h` header comment. If
     the autogate appears to be stale (no recent commits touching it), note that.
   - If the autogate is not found, suggest checking for typos and list all available
     autogates from the `WORKERD_AUTOGATES` macro.
